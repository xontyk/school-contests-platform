# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Two roles, both real school users (not just hackathon judges), since the site will be hosted publicly for them:

- **Ученики 9–11 классов**: приходят проверить, в каких конкурсах они участвуют, какой у них прогресс/балл, и скачать диплом за завершённый или выигранный конкурс. Используют с телефона и с компьютера, в перерывах между уроками.
- **Администратор/завуч**: создаёт и редактирует конкурсы, загружает списки участников (CSV/JSON), выгружает отчёты по активности в CSV. Использует с компьютера, нерегулярно (раз в несколько дней).

## Product Purpose

Школьная платформа для анонса конкурсов, учёта участия школьников и выдачи дипломов. Цель — заменить разрозненные объявления на бумаге/в чатах единым местом, где ученик видит свой прогресс и может скачать подтверждение участия, а администратор ведёт конкурсы и отчётность без лишней бюрократии.

## Positioning

Лёгкий, полностью клиентский инструмент (без сервера и без регистрации инфраструктуры) — школа может развернуть и показать работающий прототип за часы, а не недели. Отличие от типичной школьной CMS: прозрачная для ученика система прогресса/уровней (геймификация участия) плюс мгновенная генерация персонального диплома прямо в браузере.

## Operating Context

- Запускается из браузера (desktop и мобильный), без установки и без бэкенда — данные живут в localStorage конкретного устройства.
- Демонстрационный тестовый набор данных (4 конкурса, 5 учеников, 2 администратора) предзагружается при первом открытии.
- Импорт участников через CSV/JSON-файл — администратор готовит список заранее (например, выгружает из классного журнала).
- Площадка для демонстрации на защите хакатона и для публичного доступа по ссылке (GitHub Pages), поэтому должна выглядеть завершённой и убедительной без закадрового пояснения.

## Capabilities and Constraints

- Полностью статический сайт (HTML/CSS/vanilla JS), без сборки, без зависимостей — технический выбор уже сделан и сохраняется.
- Данные не синхронизируются между устройствами/пользователями (ограничение localStorage) — это осознанный компромисс прототипа, не ошибка.
- Роли: ученик и администратор, с раздельной навигацией и защитой страниц по роли.
- Дипломы: скачивание готового SVG-шаблона и опциональная персонализированная PNG-генерация на canvas.
- Тестовые логины захардкожены и показаны прямо на экране входа — это ожидаемое поведение демо-прототипа, не секрет для скрытия.

## Brand Commitments

Названия школы/бренда нет — используется обобщённое название «Платформа школьных конкурсов». Эмодзи-иконки (🏆, 🛠) в текущей навигации — временные плейсхолдеры, не закреплённый брендинг.

## Evidence on Hand

- Техническое задание хакатона (`Техническое задание.pdf`, предоставлено пользователем) с требованиями для группы 9–11 классов: схема данных, эмулированный API-слой, роли, админ-панель, личный кабинет, README с планом масштабирования.
- Рабочий прототип уже реализован: `index.html`, `student.html`, `admin.html`, `js/db.js`, `js/api.js`, `js/common.js`, `js/diploma.js`, `js/student.js`, `js/admin.js`, `css/style.css`.
- Нет логотипа, фирменных цветов или реальных фотографий школы — использовать нейтральную систему (иллюстративные формы/иконки), без выдуманных реальных отзывов или кейсов.

## Product Principles

1. Ученик должен за один взгляд понимать свой прогресс и видеть, что делать дальше (подать заявку / скачать диплом).
2. Администратор не должен тратить больше пары минут на создание конкурса или импорт участников.
3. Прототип не имитирует бэкенд видимостью — чётко демонстрирует архитектуру (API-слой), которую легко заменить на реальный сервер.
4. Дизайн должен выглядеть завершённым и профессиональным при публичном показе по ссылке, не только во время презентации с пояснениями.

## Accessibility & Inclusion

Специфических требований не зафиксировано. Целевая аудитория — школьники и учителя разного уровня владения техникой, интерфейс должен быть понятен без инструкций.
