# Портал достижений лицея

Портал учёта достижений лицея по физике, математике и информатике
(хакатон, группа **9–11 классы**): конкурсы, портфолио, рейтинг, именные
дипломы, роли «ученик» / «учитель», Telegram-бот и общая база данных.

**Сайт:** https://xontyk.github.io/school-contests-platform/ ·
**Бот:** [@achievementsportal_bot](https://t.me/achievementsportal_bot)

## Архитектура

```
 браузер (GitHub Pages)                     ноутбук / сервер
 index · login · student · teacher          bot/bot.py (aiogram)
        │  supabase-js + anon-ключ                 │ httpx + service_role-ключ
        ▼                                          ▼
 ┌──────────────────────── Supabase ─────────────────────────┐
 │ Auth: e-mail + код, пароли (bcrypt), сессии JWT            │
 │ PostgreSQL: profiles · contests · participations ·         │
 │             achievements · award_log                       │
 │ Row Level Security на каждой таблице                       │
 │ RPC (SECURITY DEFINER): одобрение заявок, проверка,        │
 │   начисление и отмена наград, рейтинг                      │
 └────────────────────────────────────────────────────────────┘
```

* **Данные централизованы**: сайт и бот работают с одной базой PostgreSQL,
  изменения видны сразу на всех устройствах.
* **Права проверяет база, а не браузер.** anon-ключ на сайте публичный по
  замыслу Supabase: он даёт ровно то, что разрешают политики RLS. Всё, что
  меняет баллы, — это функции в базе, которые сами проверяют роль учителя.
* **Слои фронтенда:** `js/config.js` (подключение) → `js/api.js` (единый
  API-слой, страницы не знают о Supabase) → `js/student.js`, `js/teacher.js`,
  `js/login.js`.

## Схема базы данных

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `profiles` | профиль пользователя (1:1 с `auth.users`) | ФИО, класс, `role` (student/teacher), `status` (pending/approved/rejected), `telegram_chat_id` |
| `contests` | объявления конкурсов | тип (олимпиада/проект), предмет, уровень, даты, статус, учебный период |
| `participations` | заявка ученика на конкурс | `result` (registered/participant/3/2/1/absent), ссылка на выданную награду |
| `achievements` | достижения и награды | категория, предмет, уровень/место/часы, баллы, `status` (pending/approved/rejected/revoked), источник (ученик/учитель/конкурс/бот) |
| `award_log` | журнал: кто, когда, сколько и почему начислил или отозвал | действие, баллы до/после, причина, автор |

**RPC-функции учителя** (каждая проверяет роль и пишет в `award_log`):
`approve_registration`, `reject_registration`, `verify_achievement`,
`revoke_achievement`, `teacher_add_achievement`, `set_participation_result`.
**Чтение:** `get_rating` (агрегаты, без чужих записей), `get_public_stats`
(числа для лендинга), `create_telegram_link_code`.

## Роли и процессы

**Регистрация.** E-mail → Supabase присылает код → пароль, ФИО, класс →
заявка в очереди. Учитель принимает её (выбирает роль: ученик или учитель)
или отклоняет с причиной. До одобрения войти нельзя, причину отказа
человек видит при попытке входа.

**Конкурсы.** Учитель публикует объявление, ученики подают заявку в один
клик. После конкурса учитель ставит каждому результат: призовое место или
участие **начисляет** баллы (они появляются в рейтинге и на карте, открывается
диплом). Если результат выставлен по ошибке, учитель меняет его с указанием
причины: прежняя награда **отзывается**, новая начисляется, вся история
остаётся в журнале.

**Достижения.** Ученик добавляет достижение на сайте или в боте (по желанию
со ссылкой на грамоту) → учитель подтверждает (может скорректировать баллы)
или отклоняет с комментарием → любое начисление можно позже **отозвать** с
причиной.

**Портфолио.** Сводка по категориям и списку подтверждённых достижений,
печать или сохранение в PDF, именной диплом PNG за каждое подтверждённое
достижение.

**Рейтинг.** Баллы по физике, математике и информатике, фильтры по классу и
периоду (четверть / учебный год), топ-10, выгрузка в Excel для учителя (оформленная таблица с итогами, `js/rating-export.js`).

## Защита от накрутки и краевые случаи

* **Ученик не может задать себе баллы**: триггер `prepare_achievement`
  при сохранении пересчитывает баллы по таблице, ставит «на проверке» и
  запрещает добавлять достижение от чужого имени.
* **Два учителя подтверждают одно достижение одновременно**:
  `verify_achievement` меняет только запись в статусе `pending` под
  блокировкой строки. Второй учитель получит сообщение «уже проверено»,
  двойного начисления не будет.
* **Чужой диплом**: подтверждает учитель (можно приложить ссылку на
  документ); после ошибки — отзыв с причиной, а не удаление.
* **Ученик не может повысить себе роль**: триггер `protect_profile`
  разрешает ученику менять только ФИО (а класс — до одобрения).
* **Повторная регистрация** на тот же e-mail не перезаписывает заявку: сайт
  покажет «уже зарегистрированы» или «заявка на рассмотрении».
* **Пароли** хранит и хеширует Supabase Auth (bcrypt); SQL-инъекции
  исключены: все запросы параметризованы (PostgREST/RPC).

## Система баллов

| Категория | Уровень | Участие | 3 место | 2 место | 1 место |
|---|---|---|---|---|---|
| Олимпиада | школьный / муниципальный / региональный / всероссийский / международный | 2 / 5 / 10 / 20 / 30 | 5 / 10 / 20 / 40 / 60 | 6 / 12 / 25 / 50 / 80 | 8 / 15 / 30 / 60 / 100 |
| Проект | школьный / городской / региональный | 5 / 10 / 15 | 8 / 14 / 20 | 10 / 16 / 25 | 12 / 20 / 30 |
| Академическое | — | 5 | | | |
| Волонтёрство | — | 1 балл за 2 часа, не больше 10 за заявку | | | |

Проекты стоят меньше олимпиады того же уровня, потому что у них нет единого
объективного судейства. Потолок у волонтёрства нужен, чтобы количество часов
не обесценивало результаты в олимпиадах. Источник правды — функция
`calc_points` в `supabase/schema.sql`, а `js/points.js` — её копия для
мгновенного предпросмотра.

## Запуск

### 1. База данных (один раз)
1. Supabase → **SQL Editor** → вставить `supabase/schema.sql` → **Run**.
2. **Authentication → URL Configuration**: *Site URL* —
   `https://xontyk.github.io/school-contests-platform/`, в *Redirect URLs*
   добавить `https://xontyk.github.io/school-contests-platform/**` и
   `http://localhost:5173/**`. Без SMTP письмо приходит со ссылкой: она
   возвращает на `login.html`, и регистрация продолжается с шага «Пароль и ФИО».
3. **Код в письмах.** Шаблоны Supabase по умолчанию содержат только ссылку,
   а редактировать их можно только после подключения SMTP (пункт 4). Затем в
   **Authentication → Emails → Templates** замените текст трёх шаблонов
   готовыми файлами из `supabase/email-templates/`: *Confirm sign up* →
   `confirm-signup.html`, *Magic link* → `magic-link.html`, *Reset password* →
   `reset-password.html`. В письме будет крупный код и кнопка-ссылка; сайт
   принимает и то и другое.
4. **Обязательно для настоящих пользователей.** Встроенная почта Supabase
   отправляет всего пару писем в час (ошибка «Почтовый лимит исчерпан»).
   Подключите SMTP в **Authentication → Emails → SMTP Settings**, например
   Gmail: host `smtp.gmail.com`, port `465`, user — ваш Gmail, password —
   *пароль приложения* (Google-аккаунт → Безопасность → двухэтапная
   аутентификация → Пароли приложений). Затем поднимите лимит в
   **Authentication → Rate Limits** (*emails per hour*).

### 2. Бот и учитель
```
cd bot
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```
В `bot/.env` впишите `SUPABASE_SERVICE_KEY` (Project Settings → API Keys →
Legacy → `service_role`). Этот ключ хранится только локально и в git не
попадает (`.gitignore`). Затем:
```
.venv\Scripts\python admin.py teacher you@mail.ru "Фамилия Имя Отчество"   # первый учитель, пароль спросит
.venv\Scripts\python bot.py       # бот работает, пока запущен
```
Первого учителя создаёт `admin.py` (без письма), дальше учитель сам
принимает заявки и меняет роли во вкладке «Пользователи».
Главного администратора назначает `python admin.py make-admin you@mail.ru`.
Во вкладке «Пользователи» у него есть «Создать пользователя»: аккаунт с
логином и паролем без письма, сразу с ролью (ученик / учитель /
администратор) и статусом (одобрен или на рассмотрении). Это делает функция
`admin_create_user` в базе, служебный ключ на сайт не попадает.
Забытый пароль восстанавливается на сайте («Забыли пароль?» → письмо со
ссылкой → новый пароль). Если письмо не доходит, владелец задаёт пароль
сам: `python admin.py password user@mail.ru`.
`python seed.py` заливает демо-данные (учитель `teacher@lyceum.ru`, ученики
`*@lyceum.ru`), `python admin.py clear-demo` удаляет их.

### 3. Сайт
Сайт статический: GitHub Pages или любой статический сервер
(`python -m http.server` в корне проекта). Сборка не нужна.

## Сценарий демонстрации (≈60 секунд)
1. Лендинг → афиша конкурсов из базы → «Зарегистрироваться» → e-mail →
   код из письма → ФИО и пароль.
2. Учитель: «Заявки» → принять с ролью «ученик». «Пользователи» → сменить
   роль или класс любому зарегистрированному.
3. Учитель: «Конкурсы» → участники → поставить «1 место» → баллы начислены.
   Сменить на «участник» с причиной → прежняя награда отозвана (история).
4. Ученик: карта созвездий, портфолио → «Диплом» (PNG) →
   «Портфолио в PDF» → рейтинг с фильтрами.
5. «Подключить Telegram» → в боте `/rating`, `/add` → учитель подтверждает →
   бот присылает уведомление.

* Значки и уровни за серии достижений.
