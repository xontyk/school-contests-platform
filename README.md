# Портал достижений лицея

Прототип портала учёта достижений лицея по физике, математике и
информатике (хакатон, возрастная группа **9–11 классы**). Полностью
клиентское решение — сервер не требуется, все данные хранятся в
`localStorage` браузера.

## Запуск

Бэкенд не нужен. Открыть `index.html` в браузере (двойной клик,
либо `File → Open`, либо через любой статический сервер). При первом
запуске автоматически создаются тестовые данные.

## Архитектура и «API-слой»

Три независимых слоя — при подключении реального бэкенда меняется
только нижний:

1. **`db.js`** — хранилище поверх `localStorage`. Generic CRUD
   (`getAll/getById/insert/update/remove`) + тестовые данные.
2. **`api.js`** — бизнес-логика и контракт API. Все методы —
   `async`/`Promise` с имитацией сетевой задержки, как у настоящего
   REST-клиента: `api.auth` (вход + 3-шаговая регистрация),
   `api.registrations` (очередь заявок для учителя), `api.users`,
   `api.achievements` (CRUD + верификация), `api.rating` (агрегация
   баллов), `api.reports` (CSV).
3. **Страницы** (`login.js`, `student.js`, `teacher.js`) работают
   только через `api.*`.

Переход на настоящий бэкенд — замена реализации внутри `api.js` на
`fetch('/api/...')`; сигнатуры методов и код страниц не меняются.

## Разграничение ролей и регистрация

- **Будущий пользователь**: e-mail → код подтверждения (демо-режим —
  код показан прямо в интерфейсе, реальная почта не отправляется) →
  пароль + ФИО + класс → заявка уходит в очередь учителю. Доступа к
  порталу до одобрения нет.
- **Учитель**: видит очередь заявок на регистрацию, одобряет
  (с назначением роли «ученик»/«учитель») или отклоняет с причиной;
  проверяет достижения учеников (подтверждает/отклоняет с
  комментарием, может скорректировать баллы); может добавить
  достижение любому ученику напрямую — оно сразу подтверждено;
  видит рейтинг и выгружает его в CSV.
- **Ученик**: карта созвездий (портфолио), список своих достижений
  со статусами, форма добавления нового достижения (баллы видны
  сразу, до отправки), рейтинг лицея с фильтрами по классу/предмету,
  печать портфолио (браузерная печать с отдельной раскладкой).

## Система баллов

Прозрачная и обоснованная: баллы растут с уровнем и местом, видны
ученику ещё до отправки заявки (честно — учитель может
скорректировать, но не «чёрный ящик»). Полная таблица — на лендинге
(`index.html` → «Система баллов»).

- **Олимпиада**: школьный (2/5/6/8) → муниципальный (5/10/12/15) →
  региональный (10/20/25/30) → всероссийский (20/40/50/60) →
  международный (30/60/80/100) [участие/3/2/1 место].
- **Проект**: школьный (5/8/10/12) → городской (10/14/16/20) →
  региональный (15/20/25/30) [участие/3/2/1 место] — меньше, чем
  олимпиада того же уровня: проект обычно не имеет единого
  объективного судейства, как предметная олимпиада.
- **Академическое достижение**: фиксированные 5 баллов — поощряет
  регулярную успеваемость без переоценки относительно олимпиад.
- **Волонтёрство**: 1 балл за 2 часа, потолок 10 баллов за одну
  заявку — иначе количество часов обесценивало бы качество помощи
  и соревновательные категории.

## Сигнатурная деталь интерфейса: карта созвездий

Подтверждённые достижения ученика рисуются как звёзды на SVG-карте
(`js/constellation.js`): кластер на предмет (физика/математика/
информатика) плюс кластер «проекты и волонтёрство», размер и яркость
звезды растут с баллами, звёзды внутри кластера соединены линиями как
настоящее созвездие. Позиции детерминированы по id достижения — карта
не «дёргается» между перерисовками с теми же данными.

## Сценарий демонстрации (≈60 секунд)

1. Лендинг → «Зарегистрироваться» → ввести e-mail → увидеть код
   (демо) → подтвердить → ФИО и пароль → заявка отправлена.
2. Вход под `teacher@lyceum.ru` → «Заявки на регистрацию» → одобрить
   новую заявку с ролью «ученик».
3. «Достижения на проверке» → подтвердить одно достижение с
   комментарием.
4. Выход → вход под `petr@lyceum.ru` → «Моя карта»: звёзды,
   баллы по предметам → «Достижения» → добавить новое (баллы видны
   сразу) → «Рейтинг»: своя позиция подсвечена.
5. Кнопка «Печать портфолио» — печатная раскладка без навигации.

## Краевые случаи, учтённые архитектурой

- **Два учителя подтверждают одно достижение одновременно**: статус
  меняется один раз (последняя запись в `localStorage` побеждает —
  в прототипе без сервера это осознанное ограничение однопользова-
  тельского хранилища; на реальном бэкенде решается уникальным
  индексом/транзакцией при переходе на БД, см. «План развития»).
- **Ученик пытается зарегистрироваться второй раз на тот же e-mail**:
  `api.auth.requestCode` отклоняет, если e-mail уже есть среди
  пользователей или уже есть необработанная заявка.
- **Накрутка рейтинга**: баллы в `api.rating.compute` считаются
  только по достижениям со статусом `approved` — заявленные, но не
  подтверждённые баллы в рейтинг не попадают ни на одном экране.

## План развития (явно не реализовано в статическом прототипе)

Эти пункты из полного ТЗ 9–11 класса требуют настоящего сервера и
осознанно не имитируются как «как будто работающие» — see PRODUCT.md:

1. **Реальный e-mail**: сейчас код подтверждения демонстрируется в
   интерфейсе. На бэкенде — транзакционная отправка через
   SMTP/провайдера (например, Postmark/SendGrid) с TTL на код.
2. **База данных**: перенос схемы `users`/`registrationRequests`/
   `achievements` в PostgreSQL с внешними ключами и уникальным
   индексом `(userId, contestId)`-аналогом для защиты от дублей.
3. **Telegram-бот**: отдельный сервис на `aiogram`/`node-telegram-
   bot-api`, читающий ту же БД — просмотр рейтинга, добавление
   достижения, push-уведomление о решении учителя.
4. **Хранилище файлов** для подтверждающих ссылок на грамоты/дипломы
   (S3-совместимое) — поле `proofUrl` в схеме уже предусмотрено.
5. **Графики динамики** баллов по месяцам/направлениям поверх уже
   существующей агрегации `api.rating.compute`.

## Примечания

- Пароли хранятся в открытом виде в `localStorage` — осознанное
  упрощение прототипа без сервера, не для продакшена.
- Код содержит комментарии к ключевым функциональным блокам
  (заголовки файлов `db.js`, `api.js`, `points.js`,
  `constellation.js`, `student.js`, `teacher.js`).
